# Octop on Railway

One-click [Octop](https://github.com/TencentCloud/Octop) for Railway: Tencent Cloud's self-hosted, multi-user, multi-agent AI assistant (MIT). You get the web dashboard, the REST/WebSocket API, agents ("experts") with memory, knowledge bases, skills, scheduled tasks and chat-app channels, in one service with one volume.

**Version:** Octop **1.0.3b7**, official image `ghcr.io/tencentcloud/octop:1.0.3b7@sha256:e80f438665c50e4ee85071628494f4ad4240c4e357c2d858e08d1423a11686ac` (upstream's default "lite" image).

## What the template deploys

| Service | What it does | Port / health | State |
|---|---|---|---|
| Octop (public) | Octop server: dashboard, API, agents, cron, channels. Built from this repo's `Dockerfile` | `PORT` 8088, `/api/health` | Railway volume at `/data` (SQLite database, agent workspaces, uploads, keys) |

## Variables

| Variable | Default | What it is |
|---|---|---|
| `LLM_API_KEY` | *(you enter it)* | API key of your model provider. The only prompt. |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | OpenAI-compatible base URL. Known providers (DeepSeek, OpenRouter, Groq, Gemini, Moonshot, Qwen/DashScope, …) are matched to Octop's built-in presets. |
| `LLM_MODEL` | `gpt-5-mini` | Model id used by default. |
| `OCTOP_ADMIN_USERNAME` | `admin` | First admin's username. |
| `OCTOP_ADMIN_PASSWORD` | generated | First admin's password (generated by Railway; read it in the service's Variables tab). |
| `OCTOP_ADMIN_LOCALE` | `en` | Admin's UI language: `en` or `zh`. |

The admin is created on the first boot from these variables, so there is no open setup wizard. Changing `OCTOP_ADMIN_PASSWORD` later does **not** change the password: change it in Octop (avatar → Account). Changing the `LLM_*` variables takes effect on the next restart: the provider for that base URL is added or updated and its model becomes the default. You can add more providers in **Settings → Models**.

## After deploy

1. Open the service's public URL and sign in as `admin` with `OCTOP_ADMIN_PASSWORD`.
2. A first expert ("General Expert") is ready in the chat page; send it a message.
3. Invite users and add more experts, channels (Telegram, Discord, Feishu, …) and scheduled tasks from the dashboard.

## Memory and limits

- Idle the server uses about 300 MB, so it runs on a 0.5 GB plan for chat with a hosted model. Large knowledge-base imports, the browser tool and many parallel agents need more: give the service 1–2 GB for heavy use.
- Agents run shell and file tools inside the container, confined to their workspace. Octop's Docker-sandbox and remote-desktop features need Docker or a virtual display and are not available on Railway.
- The "full" image extras (local OCR, local embeddings, virtual desktop) are not included; use a hosted embedding provider for knowledge bases.

## Updates

This template builds from this repository. When a new Octop release is tested here, the pinned version in `Dockerfile` is bumped on `main` and Railway shows an "update available" notice on your project. Read [CHANGELOG.md](CHANGELOG.md) before you apply it. Your data stays on the `/data` volume. Octop's own in-app updater is not used on Railway.

## Files

- `Dockerfile`: the pinned official image, bubblewrap, and the start wrapper.
- `railway/start.sh`: creates the admin on first boot, applies the `LLM_*` variables, starts Octop (a crash exits non-zero, so Railway restarts it).
- `railway/setup.py`: sets the admin's language and the model provider.
- `railway/first_expert.py`: gives the admin a first expert on the first boot.
